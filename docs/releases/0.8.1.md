# codr 0.8.1

codr 0.8.1 hardens two failure paths found while running 0.8.0 on macOS with a
large local OpenCode database. It contains no protocol, storage or connector
changes: the connector remains in the MDK 0.14 cohort and the bridge state
version is unchanged.

## Recovering from an incomplete session export

- An OpenCode CLI export that ends before its JSON document is complete is now
  repeated, up to three times per API shape, before the bridge gives up.
- Only incomplete reads are repeated. A missing executable, a refused command, a
  timeout, or an oversized read still fails on the first attempt.
- A session that stays incomplete is reported as such instead of the generic
  transcript error, so read failures are distinguishable in logs and in
  `check-readers`.

## Reliable launchd bootstrap during setup

- On macOS, a connector or worker bootstrap that launchd refuses right after a
  bootout (`Bootstrap failed: 5: Input/output error`) is retried once.
- A job launchd is still spawning (`state = xpcproxy`, seen on the first launch
  of a new executable) is waited for up to 90 s instead of being treated as
  failed. A job that is not spawning still fails after 15 s.
- Setup's connector upgrade no longer rolls back a working upgrade because of
  either condition.

## Verification and release limits

Local verification covers `cargo fmt --all --check`, `cargo test --locked
--tests`, strict `cargo clippy --locked --all-targets -- -D warnings`, and the
Python unit tests. The incomplete-export path is covered by a fake CLI that ends
its document early for the first attempts.

Existing 0.8.0 binaries cannot be relabelled as 0.8.1. A public 0.8.1 release
must be built from its reviewed, versioned source and pass the platform and
connector gates.
