# codr 0.9.0 build candidate

This focused candidate is based on GitHub stable `5027a14a897799b9b9924d7d1d2a99fa616e85b1`. It is not a published
release, and build-only CI artifacts are not discoverable by `/update`.

## Included scope

- Restart-safe 200-folder pagination with case-insensitive `ls <part>` filtering.
- Current-chat `/last`, optional `/recent` hour windows and original UTC dates.
- Chat-scoped `/cancel`, clearer invitations and first welcomes.
- Non-owning loopback OpenCode HTTP reads with bounded durable-log watermarks.
- Fresh Claude transcript handling, EOF-only bounded CLI retries and warning
  throttling that admits first occurrences at its 256-entry capacity limit.
- Version-independent updater fixtures and slow-read mute/wake regression coverage.
- Stable PR #16 launchd behavior and original contributor commits unchanged.

The installed focused baseline and subsequent scoped changes passed local tests
and independent reviews before assembly. Those earlier runs are not proof for
this exact candidate. Its Linux/macOS checks, formatting and strict Clippy must
pass in the build-only CI run before its four platform packages can be accepted.

## Excluded scope

No Foreman orchestration, worker-sharing filters, combined runtime, vendored MDK,
new storage cohort or SQLCipher dependency migration. The connector pin and
stable bridge/connector separation remain unchanged. The operator's dirty local
checkout and real Git index are preserved; this tree was assembled separately.

## Build and update-test gates

1. Use the existing workflow with `linux_preview=false` and the exact source SHA.
   It checks and packages Linux x86_64/aarch64 and macOS x86_64/aarch64 without
   publishing. No retained 0.8.0 artifact verifies this 0.9.0 source.
2. Record source, version, platforms, build inputs, test results, provenance,
   artifact completeness/expiry and SHA-256 checksums. Keep original run links.
3. Obtain approval before stable integration, version tag, release or install.
   The current tag workflow rebuilds before publishing; it does not promote
   manual-dispatch artifacts. Explain and retain that gate, not a duplicate run
   started merely for mirroring.
4. Publish approved source/release on GitHub first. Mirror matching refs, exact
   unchanged assets, checksum files, release metadata and contributor notes via
   ngit/Blossom. Tom approves `devbox-amber` signing requests. Verify downloaded
   mirrored bytes against GitHub originals; see [MIRRORING.md](../MIRRORING.md).
5. Only then test `/update` from the owner's phone. Check it offers 0.9.0 before
   confirming. Preserve accounts, chats, history, accepted deliveries and sync
   controls. Do not pre-install, change updater trust roots, bypass checks or
   migrate connector storage to make the test pass.

Local source/binary installation, CI artifacts, published stable source/tag,
GitHub release and verified ngit mirror remain separate states.
